<section class="article-section" id="why-stuck">
## 為什麼很多學生卡在「不知道要做什麼」？

很多高中生其實有能力做 Side Project，但最常見的狀況是：一直想，卻從來沒開始。背後通常有幾個原因：

- 覺得自己還不夠強，要再等一下
- 想到的題目太大，不知道從哪裡切入
- 做到一半失去方向，不確定繼續做有沒有意義
- 不知道什麼樣的專案對申請真正有幫助

這些問題的根本原因，通常不是能力不足，而是選題方式出了問題。真正好的 Side Project，很少是從「我要做一個很厲害的東西」開始，而是從「有一個問題讓我很好奇，或者有一件事我想改善」開始。
</section>

<section class="article-section" id="common-mistake">
## 最常見的錯誤開始方式

很多人第一個反應是去查「現在最熱門的 Side Project 是什麼」。這其實是一個陷阱。

別人熱門的題目，不代表適合你。選了一個自己沒有真正興趣的題目，做到一半通常就會停掉。就算做完了，面試的時候也很難說清楚「為什麼做這個」——而這恰好是評審最常追問的問題。

真正應該先思考的不是「什麼熱門」，而是：

- 我想申請什麼科系？這個科系最在意什麼能力？
- 我平常對什麼東西有興趣，願意花時間鑽研？
- 我生活裡有沒有哪件事讓我覺得「這可以更好」？

Side Project 最好的起點，通常是「科系方向 × 個人興趣 × 可執行性」三個維度的交叉點。
</section>

<section class="article-section" id="reverse-by-field">
## 從科系方向反推：各方向的具體思路

不同科系的評審在意的能力不一樣，反推出來的 Side Project 方向也不同。以下是幾個方向的具體思路：

- **資工 / AI / 電機**：評審在意問題拆解能力、實作能力與系統思維。如果你喜歡 AI，可以從「AI 工具解決一個生活中的小問題」開始，比如 AI 摘要工具、學習助手、或自動化腳本。如果你喜歡遊戲或社群，Discord Bot 是很好的入門選擇，因為可以快速做出可運作的東西。想透過競賽快速累積作品素材，可以參考 [Hackathon 參加指南](/pages/resources/hackathon-guide.html)。
- **商管 / 創業**：評審在意市場觀察能力與商業思維。從你最常用的產品或服務出發，問自己「哪裡做得不夠好？」品牌帳號經營、使用者訪談、或一個解決小問題的 MVP，都能展現你對「使用者需求」的敏感度。
- **醫學 / 生科 / 心理**：評審在意研究能力與問題意識。從你科展、課堂或日常生活裡注意到的現象開始，試著設計一個小型問卷研究或文獻回顧。重點不是結論多驚人，而是你的問題是不是自己發現的、研究方法是不是你自己設計的。
- **設計 / 傳播**：評審在意視覺表達與敘事能力。選一個你真的有感覺的議題或品牌，做一個重新設計的提案——不論是 UI 介面、品牌識別，還是一支短影片。重點是能說清楚你的設計決策背後的邏輯。
- **工程 / 機械**：評審在意動手能力與系統整合。從一個你想解決的物理世界問題開始，不管是環境監測、自動控制，還是改良一個現有的裝置。讓成果有 Demo 影片和說明文件，比一個沒有說明的複雜系統更有說服力。
</section>

<section class="article-section" id="check-fit">
## 如何判斷一個題目適不適合你？

選到題目之後，可以用五個問題確認它是否值得投入：

- **我對這個題目有沒有興趣？** 如果完全沒有興趣，大概做兩週就會停掉。
- **我能不能在 1 到 3 個月內做出第一版？** 太大的題目很容易卡死。縮小範圍，先做出一個能展示的小版本。
- **成果有沒有辦法展示？** <a href="https://github.com" target="_blank" rel="noopener noreferrer">GitHub</a>、網站、報告、影片、社群帳號——有沒有讓別人可以自己去確認的東西。
- **做這個我能學到什麼新東西？** 好的 Side Project 通常會逼你查資料、Debug、學新工具，這個過程本身就是評審想看到的。
- **做完之後，我願不願意繼續優化？** 真正有說服力的 Side Project，通常不是一次性活動，而是可以持續迭代的東西。

五個問題裡如果有三個以上是「是」，這個題目通常值得動手。
</section>

<section class="article-section" id="first-step">
## 最好的開始方式：做一個很小但完整的版本

很多人都在等：等自己變強、等有完美點子、等時間變多。但真正能做出成果的人，通常只是做了一個「很小但能完成」的版本。

例如：

- 一頁式[個人網站](/pages/resources/portfolio-website.html)，介紹自己的興趣和在做的事
- 一個只有單一功能的 Discord Bot
- 一份針對一個問題的問卷研究，附上資料視覺化
- 一個品牌帳號，先把前 10 篇貼文做好
- 一個 <a href="https://www.kaggle.com" target="_blank" rel="noopener noreferrer">Kaggle</a> Notebook，針對一個公開資料集做完整分析

完成第一版之後，你才會知道下一步該做什麼，也才能從使用者或外部的反應裡得到真正的修正方向。不要等到「準備好了再開始」——開始本身，就是讓你準備好的過程。題目確定後的完整執行步驟，可以參考[從 0 到 1 的 Side Project 執行流程](/pages/resources/side-project-from-zero.html)。
</section>
