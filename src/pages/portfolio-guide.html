為什麼現在需要 Portfolio？

在 108 課綱強調自主學習與學習歷程的脈絡下，學生不只需要完成資料上傳，更需要能說清楚自己如何探索、如何行動、如何反思。Portfolio 的價值不在於取代學習歷程，而是補上 PDF 難以呈現的互動證據、作品脈絡與長期累積。

串接個人主線

讓獎狀、專題、活動不再只是清單，而是變成能說明你為什麼適合某個學群的故事。

建立真實證明力

用 GitHub、影片、設計稿、實驗紀錄等證據，補上 PDF 備審容易缺少的可信度。

形成長期資產

個人網站可以一路延伸到大學、實習、研究與求職，是一份可以更新的數位履歷。

評審教授內心話

空洞的包裝，不如真實的反思。

很多學生放滿證書與漂亮排版，但教授真正想確認的是：你遇到什麼問題、如何學會方法、如何修正錯誤，以及下一步想走向哪裡。

與挫折共處

比起完美成果，更重要的是你如何處理 bug、失敗與限制。

學習歷程一致

主線不能像臨時拼湊，而要看得出長期累積。

實務操作素養

程式碼、數據、影片、實驗紀錄都能提高可信度。

學科熱情

熱情不是口號，而是你願意投入時間找資料、做測試、修正方向。

基礎概念

Portfolio 是什麼？

Portfolio 是能展現能力亮點與探索軌跡的動態作品集。它不是取代備審 PDF，而是補上 PDF 最難呈現的互動、證據與長期更新能力。

比較維度 個人 Portfolio 網站 傳統備審 PDF
排版自由度 可用卡片、動線、互動與多媒體呈現個人主線。 受格式限制，容易變成文字與證明堆疊。
證據呈現 可連結 GitHub、影片、設計稿、Demo 與數據。 多數只能放截圖與簡短說明。
長期價值 可持續更新到大學、實習、研究與求職。 常在申請結束後失去用途。
核心目的 說清楚你如何學習、行動、反思與累積。 多半偏向合規上傳與成果羅列。

什麼是「個人主線」？

如果高中三年的各項探索是一顆顆散亂的珍珠，個人主線就是把它們串起來的那條線。沒有主線，教授只會看到很多活動；有了主線，教授才能看懂你如何形成方向。

沒有主線

鋼琴紀錄、競賽證書、英文心得各自存在，教授看不出你想申請什麼，也看不出你如何累積能力。

有主線

用「開源硬體推動校園永續」串起自學、實作、校園觀察與申請動機，讓每段經歷都服務同一個方向。

Step by Step

從 0 開始建立 Portfolio

先不要急著選工具。最重要的是先把素材整理成主線，再決定用什麼形式呈現。

Step 1

整理歷史探索與素材

不要急著排版。先把高中三年做過的活動、報告、競賽、自主學習、社團任務與 Side Project 全部列出來。

Tip

此階段不要自我審查，重點是累積素材池。照片、程式碼、簡報、報告、影片與獎狀都要標記連結。

Example

例如：高一物理水火箭、高二微控制器自主學習、寒假資工工作坊、GitHub 作業程式碼、社團粉專經營數據。

列出至少 8 個探索經歷
每個經歷至少找到 1 個證明連結
把檔案整理到雲端資料夾

Step 2

萃取個人核心主線

在凌亂經歷中尋找交集：你持續在意什麼問題？你常常主動學什麼？你解決問題時偏好的工具是什麼？

Tip

試著把主線濃縮成一句話，例如：用資料分析理解校園行為，或用開源硬體改善生活問題。

Example

例如：用開源硬體推動校園永續、用資料視覺化理解社群互動、用設計方法改善學生資訊落差。

用 20 字內描述核心熱情
選出 3 個最能證明主線的作品
刪除和主線無關的素材

Step 3

撰寫 About Me

不要從家庭背景或個性形容詞開始。直接說明你的學習信念、代表實踐、申請方向與未來想解決的問題。

Tip

使用三段式：信念 → 高中實踐亮點 → 大學想延伸的學術方向。

Example

例如：我相信好的科技學習不只在課本裡，而在於能否把一個真實問題拆成可測試、可修正、可分享的實作。

300 字內完成
包含具體代表作
避免熱情、努力、積極等空泛詞

Step 4

撰寫 Projects 專案解構

Projects 是 Portfolio 核心。每個專案都要說清楚 Situation、Action、Result、Insight。

Tip

不要只寫結果，教授更想看你如何面對問題、debug、修正方向與形成下一步。

Example

例如：因為校門口車流壅塞，我用 Raspberry Pi + OpenCV 做車流偵測，最後完成 Demo 影片與 GitHub 紀錄。

寫出痛點與問題情境
列出實際方法與工具
補上成果數據與反思

Step 5

整理 Skills 能力矩陣

不要寫 Python 80%、領導力 90%。改用技能分類與代表作品證明能力。

Tip

每個技能後面要能接出一個作品或任務，例如：Python｜OpenCV 車流分析系統。

Example

例如：資料分析｜問卷清理與圖表製作；Figma｜使用者流程圖與高擬真原型；Git｜專案版本管理。

拿掉百分比能力條
每個技能對應代表作
只保留面試能回答的技能

Step 6

選擇工具與部署方式

依照時間、技術能力、申請方向選工具。不是越難越好，而是能否穩定呈現與更新。

Tip

文組與初學者可從 Notion / Carrd 開始；資工與工程方向可考慮 GitHub Pages / Vercel。

Example

例如：文組用 Notion + Super 快速公開；設計組用 Framer / Webflow；資工組用 GitHub Pages 展示程式脈絡。

確認手機版可讀
所有連結可點擊
圖片壓縮後再上傳

Step 7

測試、回饋與迭代

請家長、同學或老師用 3 分鐘試看，確認他們能不能說出你的主線與代表能力。

Tip

Portfolio 是動態資產，第一次完成後仍要持續修正。

Example

例如：請對方看完首頁後回答：你想申請什麼方向？你最強的證據是什麼？哪個作品最有記憶點？

3 分鐘內看懂主線
沒有錯字與失效連結
CTA 與聯絡方式清楚
Structure

推薦架構模板

一份好的 Portfolio 不需要頁面很多，但每個區塊都要對應到教授想確認的能力。

模組建議比重用途
Hero 首屏15%姓名、主線、目標學群、最關鍵的一句話。

    Tools
    
工具指南

    
工具不是越難越好，而是要符合你的時間、技術門檻與申請目標。

  


  

    
    
    
    
    
  


  
  

    零門檻開始
    
Notion

    
適合先整理素材、建立文字版作品集與簡易公開頁。

    
建議路徑：先建立素材資料庫 → 分出 About / Projects / Evidence → 公開頁面；若想更像網站，可搭配 Super / Potion 類工具包裝成個人網址。

    

      
優點
  • 上手最快
  • 適合整理資料庫
  • 不用寫程式

      
限制
  • 視覺客製有限
  • 互動與動畫較弱
  • 正式感略低

    

  


  
  

    一頁式漂亮網站
    
Carrd

    
適合想快速做出精美 landing page 的學生。

    
建議路徑：先做一頁式首頁 → 放 2–3 個代表專案 → 加入 CTA 與外部作品連結。

    

      
優點
  • 視覺乾淨
  • 成本低
  • 一頁式架構清楚

      
限制
  • 多頁內容不方便
  • 作品數多時較難管理
  • 進階互動有限

    

  


  
  

    設計與商管路線
    
Framer / Webflow

    
適合設計、傳播、商管、社科方向，想做出更精緻視覺與互動的學生。

    
建議路徑：選定模板 → 套入個人主線 → 每個專案都用問題 / 行動 / 成果 / 反思呈現，不要只做漂亮版面。

    

      
優點
  • 視覺表現強
  • 適合品牌感
  • 不一定要寫程式

      
限制
  • 學習曲線中等
  • 免費方案限制較多
  • 內容更新需有版面感

    

  


  
  

    工程 / 資工加分
    
GitHub Pages

    
適合想展示程式能力、版本紀錄與開源專案的學生。

    
建議路徑：建立 username.github.io repo → 放入 index.html → 每個專案連回 GitHub repo、commit 紀錄與 Demo。

    

      
優點
  • 技術證明力強
  • 可連接 GitHub 作品
  • 免費部署

      
限制
  • 需要基本 HTML/CSS/Git
  • 初期維護門檻較高
  • 設計需自己處理

    

  


  
  

    互動作品展示
    
Vercel

    
適合已有前端專案，或想展示互動式網站 / 小工具的學生。

    
建議路徑：將 React / Vite / Next 專案接到 GitHub → 用 Vercel 自動部署 → 每次 commit 都留下迭代紀錄。

    

      
優點
  • 部署體驗好
  • 支援現代前端框架
  • 適合互動 Demo

      
限制
  • 需要較高技術門檻
  • 需注意 API key 安全
  • 對純內容頁可能過重

    

  









  

    Cases
    
真實案例如何呈現？

    
案例不只是展示結果，而是讓教授看懂你如何從問題出發、採取行動，最後形成可遷移能力。

  


  

    
    
    
  


  
  

    
案例 A｜工程實作型學生

    
主線：從競賽動手做到工程問題解決

    
適合展示機器人、程式、實驗設計、debug 紀錄與實作影片。重點不是只說拿獎，而是解釋你如何面對技術瓶頸，如何拆解問題並驗證解法。

    

      
敘事轉換
從「我參加過比賽」改成「我如何從失敗與調整中形成工程思維」。

      
為什麼有說服力
教授可以看到的不只是獎項，而是問題拆解、測試迭代與動手能力。

      
可放證據
  • GitHub commit 紀錄
  • 操作影片
  • 設計草圖
  • 比賽或專題成果

    

  


  
  

    
案例 B｜商管資料分析型學生

    
主線：從觀察現象到提出改善方案

    
適合展示訪談、問卷、田野紀錄、資料視覺化與政策分析。重點是讓研究方法與個人關懷同時被看見。

    

      
敘事轉換
從「我關心社會議題」改成「我如何蒐集資料、驗證假設並提出可行方案」。

      
為什麼有說服力
教授可以辨識學生是否真的理解研究方法，而不是只寫理念。

      
可放證據
  • 問卷資料
  • 訪談摘要
  • 圖表分析
  • 行動方案

    

  


  
  

    
案例 C｜設計 / 傳播型學生

    
主線：從使用者需求到視覺與體驗設計

    
適合展示 Figma 原型、品牌識別、社群企劃、使用者測試與迭代紀錄。重點是說清楚你不是只做美，而是能回應需求。

    

      
敘事轉換
從「我會設計」改成「我如何理解受眾、測試方案並修正視覺溝通」。

      
為什麼有說服力
教授可以看到審美之外的問題意識、溝通策略與迭代能力。

      
可放證據
  • Figma 原型
  • 設計迭代
  • 社群數據
  • 使用者回饋

    

  









  

    Mistakes
    
教授最討厭的 Portfolio 地雷

    
以下錯誤會讓 Portfolio 看起來像包裝，而不是能力證據。

  


  

    

      

        
        
地雷一：把 Portfolio 當成雲端硬碟
所有作品都丟上去，但沒有分類、主線與篩選。教授只會覺得資訊太多，無法判斷重點。

      

    

    

      

        
        
地雷二：滿頁都是 AI 形容詞
充斥熱忱、積極、深刻體會，但缺少具體行動與成果證據。

      

    

    

      

        
        
地雷三：設計很花，但教授找不到重點
動畫、顏色、特效過多，反而阻礙閱讀。

      

    

    

      

        
        
地雷四：忽略手機版與連結測試
網站打不開、圖片過大、GitHub 連結失效，都會直接降低信任感。
