# DEBUG LOG

每修掉一個 bug 就寫一則。這份文件的投報率被嚴重低估——查表比重新 debug 便宜兩個數量級。

## 常見問題速查

| 症狀 | 多半是 | 條目 |
|---|---|---|
| （長出來之後填這裡，這張表才是真正被讀的部分） | | |

---

## 條目模板（複製這段）

```markdown
## D-001｜YYYY-MM-DD｜<一句話>

**問題描述**：
**症狀**：使用者／log 看到的實際現象（不是你的猜測）
**根因**：真正的原因。「改了就好了」不是根因。
**解方**：
**預防**：怎麼讓「這一類」bug 不可能再發生？
```

**「預防」是這份文件存在的理由。** 修好一個 bug 卻沒問「怎麼讓這類 bug 不可能再發生」，就是保證會再遇到它。

好的預防長這樣：
- 忘記 mock 就會連上正式 DB → 加一個 `autouse` fixture，讓沒 mock 的測試**直接爆炸**
- 不小心多／少一個路由沒人發現 → 加 `EXPECTED_ROUTES` 絆線
- build 過了但頁面載入就崩 → 加 headless 行為測試，並把新功能加進測試清單

這三個都是真實案例，而且都是從「預防」欄長出來的。
