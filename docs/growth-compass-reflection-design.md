# Growth Compass — 反思 / 敘事捕捉面設計

> 取代「自評問卷（Likert → 雷達圖）」。這是 v0.1 的差異化核心。
>
> 上位定位見 `positioning.md`；範圍見 `growth-compass-v0.1-scope.md`。

---

## 設計目標

捕捉面要產出的**不是分數**，是**能被顧問接手的敘事原料**。判斷一個欄位該不該存在，問一句話就好：

> 「這一欄會幫顧問更快把這段經歷講成一個故事嗎？」會 → 留；不會 → 砍。

它**不負責**回答「我適合什麼/我缺什麼」（那是顧問 + 高風險決策才做得準的事）。它只負責**把原料收乾淨**，並在過程中讓使用者嘗到一口「被看懂」。

---

## 設計原則

1. **要故事，不要量表。** 全開放式問句，禁 Likert（1–5 分那種就是策略劇場）。
2. **從具體到抽象。** 先問「你做了什麼」這種好回答的，最後才問「這跟你是誰有關係嗎」。
3. **漸進揭露，不要一次問完。** 分「快速捕捉」與「事後深掘」兩段，降低棄填。
4. **每個問題都餵向主線。** 問題的存在是為了讓「定位/主線/呈現」有素材，不是為了填滿表單。
5. **自評只當訊號，不當能力分。** 唯一允許的自評是「這段我自己講不講得清楚」——那是**要不要找顧問的訊號**，不是能力評分。

## 資料結構：一筆經歷 = 記錄層 + 敘事層

### 記錄層（🔵 來自 Lucker 匯入 / 輕量自填，唯讀為主）

| 欄位 | 說明 |
|---|---|
| `title` | 名稱 |
| `period` | 時間 |
| `type` | 競賽 / 專題 / 研究 / 實習 / 打工 / 創業 / 證照 / 社團 / 作品集 等 |
| `outcome_raw` | 客觀成果（名次、產出物） |
| `evidence` | 證明連結 / 檔案（合規前置見 scope 文件） |

> 這層**不是差異化**。能匯入就匯入，使用者不該重打。

### 敘事層（🟢 TBD 的核心捕捉面）

| 欄位 | 提問（給使用者看的文案） | 餵向 |
|---|---|---|
| `origin` | 當初**為什麼**會去做這件事？是被指派、跟風，還是自己想做？ | 動機 / 真實性 |
| `my_role` | 講具體一點：**你實際做了哪部分**？（用動詞，不要用「參與」帶過） | 貢獻釐清 / 去水分 |
| `turning_point` | 過程中**最卡的一關**是什麼？你怎麼面對的？ | 故事張力 / 韌性 |
| `change` | 做完之後，你跟做之前**有什麼不一樣**？ | 成長證據（真正的「成長」在這） |
| `meaning` | 這件事跟「**你想成為怎樣的人**」有關係嗎？它接得上你其他哪段經歷？ | 主線 / 定位 |
| `tellability` | 如果現在要你跟陌生人講這段，你覺得自己**講得清楚嗎**？（講得很清楚 / 講得出但零散 / 幾乎講不出來） | 🟡 找顧問的訊號，**非**能力分 |

> `change` 欄是衡量「成長」的正解——比重複做問卷看雷達圖變化可信得多。
> `meaning` 欄是把單筆經歷接成「主線」的關鍵，也是顧問最需要的原料。

### 鋪軌：主題標籤（為未來 Narrative Graph 預留，v1 不建圖）
每筆經歷在反思後，由顧問（或日後系統）打 1–3 個**主題標籤**（自主學習 / 跨領域 / 研究導向 / 教育 / 創業 / 設計…）。**v1 只需把欄位留著、能存標籤即可**，不做圖譜、不做自動匹配。如此未來要做「你的故事與這些成長路徑共享 DNA」時不必重建資料。標籤須扎根真實反思文字，否則又變策略劇場。網路效應來源是**顧問養的案例圖譜**，不是聚合學生資料（見 positioning / overview）。

## 互動流程：兩段式，降棄填

```
第 1 段 ── 快速捕捉（30 秒）
  匯入/選一筆經歷 → 只問 origin + my_role
  （門檻低，先讓人留下東西）

        ↓ 之後任何時間（里程碑/申請季觸發，不催月度）

第 2 段 ── 深掘（一次一題，可中斷）
  turning_point → change → meaning → tellability
  每題獨立卡片，答一題存一題，不強迫一次答完
```

- **一次一題**，不要長表單。
- 完成 `meaning` 後，給一個**質性回饋**（不是分數）：把這筆和使用者其他經歷的可能連結點出來，例如「你這段和先前那筆都圍繞『把抽象想法做成東西』——這可能是一條主線」。這就是那一口「被看懂」。
- 任何一筆 `tellability` = 「幾乎講不出來」或多筆 `meaning` 連不起來 → **觸發 CTA：與顧問聊聊怎麼把這些串成申請故事**。（交棒給人，不自動產出策略。）

## 跨經歷的「觸發問題」（軟體只問，不自動答）

這些是把產品推向「Understand Yourself」的問句，但**答案交給顧問**，軟體只負責問得好、收得齊：

- 看完你所有經歷，你覺得**哪一條線最像你**？
- 哪一筆經歷你**最想拿出來講**？為什麼？
- 有沒有哪段你做了很多、卻**不知道怎麼講**？

> 這幾題的價值在「**問出對的問題**」本身——讓使用者意識到缺的不是經歷，是呈現。這正是導向顧問的時機，不是讓系統吐出答案的時機。

## 能力標籤對照表（v1 反射模板用｜可維護清單）

> 第 1 階「被看懂」的模板，會在使用者的 `my_role`／`title` 文字裡偵測關鍵詞，命中就回拋一個「可講出口」的能力標籤。
> **實作於 [`public/js/seen.js`](../public/js/seen.js) 的 `CAPABILITIES` 陣列——改清單請兩邊同步。**
>
> 規則：由上而下取**第一個**命中者；**全部沒命中就不硬掰**，改走「你講得很具體」的反射（守住「不憑空捏造」）。新增條目時，能力描述要寫成**大人會講的一句話**，不要寫成科系或標籤名詞。

| 偵測關鍵詞（擇一命中） | 回拋的能力標籤 |
|---|---|
| 規劃 / 策劃 / 安排 / 排了 / 排程 / 計畫 / 籌備 / 統籌 | 從零規劃並執行一件事 |
| 程式 / code / coding / 開發 / 架站 / 網站 / 網頁 / app / 程式碼 / 系統 | 把點子做成真的能跑的東西 |
| 設計 / 排版 / 美編 / 繪圖 / 視覺 / 海報 / logo / 插畫 | 把想法變成看得到的設計 |
| 帶 / 領導 / 管理 / 帶領 / 主辦 / 負責 / 召集 / 幹部 / 社長 / 隊長 / 組長 | 帶人，並把責任扛起來 |
| 教 / 教學 / 講解 / 分享 / 帶課 / 家教 / 授課 | 把複雜的事講到別人聽得懂 |
| 拍 / 剪 / 影片 / 攝影 / 剪輯 / 錄製 / vlog | 用影像把事情說出來 |
| 訪問 / 採訪 / 訪談 / 田調 / 田野 | 挖出別人故事的能力 |
| 分析 / 數據 / 統計 / 資料 / 問卷 / 量化 | 用資料把問題看清楚 |
| 粉絲 / 觸及 / 流量 / 經營 / 成長了 / 追蹤 / 互動率 / 按讚 / 曝光 | 把內容做出可以衡量的成長 |
| 比賽 / 競賽 / 參賽 / 獲獎 / 得獎 / 名次 / 入圍 / 奪 | 在壓力和期限下把成果做出來 |
| 研究 / 文獻 / 論文 / 實驗 / 探究 | 研究並驗證一個問題 |
| 募款 / 義賣 / 擺攤 / 銷售 / 販售 / 商品 / 定價 / 營收 | 把東西推到真實的人面前 |
| 翻譯 / 口譯 / 筆譯 | 跨語言把意思精準傳遞 |
| 志工 / 服務學習 / 偏鄉 / 關懷 / 陪伴 / 長照 | 把在乎的事化成具體行動 |
| 企劃 / 活動 / 策展 / 展覽 / 園遊會 / 營隊 | 把一個活動從無到有辦起來 |

> 維護建議：標籤總數別爆量（命中率重於覆蓋率）；同義詞往同一列塞；若某類常出現卻沒對應列，再新增一列，並更新 `seen.js`。
