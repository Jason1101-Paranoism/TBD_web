## Executive Summary

TBD 真正的競爭優勢從來不是 AI，而是 **86+ 篇結構化內容、真實成功案例、以及顧問能力**。AI 在這裡的角色是**放大器**，不是主角。

本專案導入 FastGPT，目的是用一個「會引用真實文章帶路的 AI 導航員」，作為 TBD 官網的**第一印象信任入口（Trust Entry Point）**：讓第一次接觸的高中生與家長，在前 30 秒就感受到「這個品牌有料、可信、懂教育也懂 AI」，並被自然帶進知識庫，最終走向真人顧問。

關鍵判斷不變：**即使工具使用效果為零，第一印象與品牌價值已回本。** 而成本隨用量浮動、零使用趨近零成本、且系統保證帳單有上限，使這個投資的下檔風險極小。唯一不可妥協的，是第一印象的品質。

## 一、定位：從「吸睛」升級為「信任」

v3.0 用「吸睛入口」描述 AI 的角色。這個詞容易讓人聯想到「酷炫、噱頭、AI 展示」——但 TBD 的核心競爭力是**專業信任**，不是炫技。

所以 v3.1 正式把它定義為：

> **第一印象信任入口（Trust Entry Point）**

機制是這樣的：

```
第一次進站
   ↓
看到 AI 導航員
   ↓
發現它的回答「引用真實文章、有條理、有溫度」
   ↓
覺得「這個品牌有料、可信」
   ↓
願意繼續看下去 → 走進知識庫 → 走向顧問
```

這比「吸睛」更高級，因為它把第一眼的注意力，直接轉化成對品牌的信任——而信任正是教育服務轉換的真正貨幣。

這也解決了 v2.0 的根本矛盾：要吸引、卻又限制額度、又要登入、又要會員，邏輯互相打架。v3.1 的邏輯乾淨：

```
信任   →   導流   →   轉換
```

## 二、品牌飛輪（Content Flywheel）

v3.0 把架構寫成線性漏斗。但 TBD 其實已具備讓它**轉成飛輪**的所有零件——尤其是 Growth Compass 與成功案例庫。

```
        ┌────────────────────────────┐
        ↓                            │
     知識庫內容                       │
        ↓                            │
   AI 導航員（信任入口）               │
        ↓                            │
   Growth Compass（個人化）           │
        ↓                            │
     顧問服務                         │
        ↓                            │
     成功案例                         │
        ↓                            │
     回饋為新內容 ───────────────────┘
```

飛輪的意義：每一圈都讓下一圈更強。顧問服務產出真實案例，案例變成新內容，新內容讓 AI 導航更準、信任更高，再帶進更多人。**AI 導航員是這個飛輪的加速器，而不是一個孤立的功能。**

把企劃從「單一功能提案」提升到「產品策略」，這張飛輪圖是關鍵。AI 導航員（Phase 1）是飛輪的起點，Growth Compass（未來）是讓飛輪自轉的動力。

## 三、為什麼是現在，而不是 300 篇再做？

這是任何投資決策都會問的問題：時機對嗎？

答案是：**AI 導航的價值來自「內容的結構化程度」，而不是「文章總數」。** 86 篇已經形成完整的主題體系（申請策略、備審、材料累積、面試、科系指南、研究所、家長專區），這個結構化程度，已經足以讓 AI 導航產生價值。

內容規模與導航價值的關係：

```
20 篇  →  太少，AI 沒東西可導，淪為玩具
80 篇  →  主題體系成形，導航開始有真實價值  ← TBD 現在的位置
200 篇 →  長尾覆蓋完整，導航效果被顯著放大
```

換句話說：

- 等到 300 篇才做，等於白白浪費 80→300 這段「導航已經有價值」的成長期，也讓 AI × 教育顧問的品牌定位被同業先佔。
- 現在做，剛好卡在「內容夠用、成本夠低、定位夠新」的甜蜜點。隨著暑假成渠知識庫持續擴張，飛輪只會越轉越快。

**結論：不是文章多到一定程度才值得做，而是內容結構一旦成形就該做——而 TBD 現在正好到了這個點。**

## 四、專案目標與非目標

### 核心目標

1. 建立**第一印象信任**——讓官網在同業中「一看就不一樣、而且可信」。
2. 降低首次訪客的探索摩擦——從「不知道該看什麼」帶到「這篇就是我要的」。
3. 啟動品牌飛輪、強化漏斗頂端轉換。

### 非目標

- 不做 AI 顧問（錄取率分析、個人化規劃、備審診斷保留給真人）。
- 不追求高使用率與深互動。
- MVP 不做會員、登入、個人化紀錄。

### AI 角色定位

> AI 只負責「幫你找到答案在哪裡、該照什麼順序讀」，不負責「幫你做決定」。

## 五、產品定位

**一句話：** TBD AI 導航員——幫你找到下一步該看什麼。
**品牌定位：** Google Maps for Education（教育版導航，不是教育版顧問）。
**AI 身分：** TBD AI 成長導航員——理解問題 → 推薦內容 → 規劃閱讀順序 → 引導至適當服務。
**語氣守則：** 專業但親切、有溫度與陪伴感，避免誇大詞。核心原則：「共創，不代筆；引導，不操控；如實呈現，不憑空捏造。」

## 六、使用者體驗：第一印象就是信任

吸睛型功能的成敗集中在前 30 秒。優先序：

1. **入口要顯眼。** 首頁 hero 與知識庫首頁最上方，並作為 IG Bio / LINE 選單落點。它是門面。
2. **零摩擦。** 不登入、不擋次數即可試用。
3. **永遠能用、永遠漂亮。** 寧可功能少，也要每次互動都流暢、有條理、視覺乾淨。
4. **永遠引用真實文章。** 信任來自「回答可被驗證」——每則回答都導向真實存在的文章，這是 Trust Entry Point 的核心。

### 使用情境

**Case 1** — 使用者：我是高二自然組，想申請資工系。
AI：推薦閱讀 ①學習歷程主線是什麼 ②Side Project 如何選擇 ③資工系教授在看什麼。預估閱讀時間 25 分鐘。

**Case 2** — 使用者：活動很多但很雜怎麼辦？
AI：推薦閱讀 ①活動不是越多越好 ②如何建立主線 ③教授如何看經歷。預估閱讀時間 15 分鐘。

**Case 3** — 使用者：我想推甄研究所。
AI：推薦閱讀 ①推甄全攻略 ②推薦信規劃 ③研究計畫書撰寫。預估閱讀時間 30 分鐘。

每則回答固定結尾帶一個明確但不強迫的 CTA。

## 七、AI 導覽流程與回答格式

```
使用者問題 → FastGPT → 搜尋知識庫(RAG) → 整理答案 → 推薦文章與順序 → CTA
```

**固定五段輸出（AI 不自由發揮）：** 問題理解 / 核心建議 / 推薦文章 / 推薦閱讀順序 / 下一步建議。
固定格式同時達成成本可控、品質穩定、語氣一致——而「推薦文章」段是整個信任機制的著力點。

### Prompt 原則（工程端遵循）

1. **先承認問題**——讓使用者覺得被理解。
2. **再給閱讀方向**——指出該看什麼、照什麼順序。
3. **必須引用文章**——每個建議都對應真實存在的文章，這是信任的根。
4. **不誇大、不保證結果**——不說「一定錄取」「一鍵解決」。
5. **不把答案講完**——保留文章點擊動機，AI 是入口不是終點。

### 第一版不回答什麼（保護品牌信任）

為避免 AI 看起來像顧問、避免越界承諾，MVP 明確不回答下列問題，並改為誠實說明並引導至真人顧問：

- 錄取機率預測
- 個人備審 / 履歷診斷
- 具體選校決策
- 代寫內容
- 任何需要完整背景評估才能負責任回答的問題

遇到這類問題的標準回應：說明「這需要顧問依你的完整背景判斷」，並導向預約 CTA——把界線本身變成一次信任與轉換的機會。

**User Layer（新增）：**

- 年級：高一～高三、大一～大四
- 目標：醫學 / 電資 / 工程 / 商管 / 設計 / 教育 / 研究所
- 問題類型：不知道做什麼 / 不知道選什麼 / 不知道怎麼寫 / 不知道怎麼準備

需指定長期標籤 owner（文章會持續增加）。

## 十、成本治理：預算池制，帳單永遠有上限

v3.1 把成本邏輯升級為一個對家長與合作夥伴都有說服力的承諾：

> **TBD AI 採「預算池制」。系統設計上保證 AI 成本永遠有上限，不會出現意外暴增的帳單。**

運作方式：

```
月預算池：500 元（上限，非固定支出）
   ↓
即時監控用量
   ↓
達上限 → AI 自動降級 → 切換 Pagefind 靜態搜尋
```

成本邏輯：

- **500 元是天花板，不是固定支出。** 實際成本隨用量浮動。
- **若工具使用效果為零，成本不是 500，而是趨近於零**（只剩固定託管，無 token 消耗）。
- 用得多 = 真的有用 = 花得值；用得少 = 幾乎不花錢 = 吸睛與信任價值已兌現。
- 真正的投入是前期建置與維護工時，不是這每月 500 元——它便宜到可以當「保險」來買，最壞情況仍有第一印象保底，**所以不是賭注。**

### 治理細則

保留：模型控制（低成本模型 + RAG）、輸入限制（500 字內）、輸出限制（600 字內）、召回限制（Top 4）、月預算自動降級、前端 → TBD API → FastGPT 安全架構。

移除（與信任/零摩擦目標衝突）：訪客每日額度、登入才放寬。靠「月預算池」這個總煞車控成本，而非對個人設關卡。

## 十一、唯一不可妥協：第一印象品質下限

吸睛的反面是「看起來像隨便接的陽春 chatbot」——那會讓家長覺得 TBD 在跟風炫技，反而傷信任。

紅線：**寧可砍功能，也要守住品質。** 上線前必過檢核：

- 回答永遠流暢、不頓、不亂答；答不出來時誠實說明並導向人工或搜尋。
- 每則回答都導得到至少一篇真實存在的文章，且連結正確。
- 視覺與語氣符合 TBD 品牌（乾淨、有溫度、不誇大）。
- 桌面（1280px）與手機（375px）皆完整可用。
- 任何情況都有 fallback（預算用罄 / API 異常 → Pagefind）。

## 十二、KPI（信任導向）

先決條件：**所有指標上線前先用現有 GA4 取得 baseline。**

### 第一印象 / 信任（主指標）

- AI 導航員入口的曝光與點擊率（首頁 hero、知識庫首頁）。
- 首次互動後的留站行為。
- 自然口碑訊號（社群提及、截圖分享，質化追蹤）。

### 導航價值核心指標（新增，最重要）

- **AI 推薦文章 CTR ＝ 推薦文章曝光 → 點擊率。**
  這是整個導航是否成功的核心判準：如果 AI 回答很多人看，但推薦文章沒人點，代表導航失敗——AI 變成了終點，而不是入口。守住這個指標，才證明 AI 真的在「帶路」。

### 內容銜接與轉換

- AI → 文章整體點擊率。
- **單一轉換錨點：** 用過 AI 導航 vs 沒用過的訪客，顧問預約率差異。這條把「信任」翻譯成商業價值。

刻意不追：AI 使用率門檻、平均互動輪數（工具導向指標，與本專案目標不符）。

## 十三、Roadmap

**Phase 0（約 1 週）— 知識庫整備：** 統一 metadata、建立雙層標籤、建立文章關聯、指定 owner。

**Phase 1（約 1～2 週）— AI 導航員 MVP（本專案重心）：** 純前台 RAG 問答、推薦文章、引用來源、固定格式、CTA、Pagefind fallback；放上顯眼入口。資源全集中在把第一印象做到無懈可擊。

#### MVP 上線驗收標準（達標才上線）

- 至少完成 **30 組測試問題**，涵蓋各身份、年級、目標、問題類型。
- 每題至少推薦 **1～3 篇正確且真實存在**的文章。
- 手機版（375px）互動流暢不卡頓。
- API 異常或預算用罄時，能自動切換 Pagefind。
- 所有推薦文章連結與 CTA 連結正確可點。
- 回答符合 Prompt 原則，且不觸碰「第一版不回答」清單。

**Phase 2（未來選配，非承諾）— 會員與紀錄：** 若 Phase 1 數據顯示值得，再導入 Supabase。需先備妥未成年資料的同意與隱私政策。

**Phase 3（未來選配，非承諾）— Growth Compass 整合：** 個人化推薦、學習路徑、案例匹配——讓飛輪開始自轉。

## 十四、風險與緩解

- 第一印象做不好反而傷信任 → 品質下限紅線，不達標不上線。
- 零點擊稀釋閱讀 → AI 只導讀不答完，並以「AI 推薦文章 CTR」即時監測。
- 標籤維護長期負擔 → 指定 owner，納入新增文章流程。
- 未成年資料隱私 → MVP 不收個資；Phase 2 前備齊同意與保存政策。
- 新鮮感衰退 → 信任靠的是導向真正的好內容，由 86+ 篇深度支撐。
- 架構複雜度上升 → MVP 維持最小集合，後台延後。

## 十六、下一步執行清單

依相依性排序，前項通常是後項的前提：

1. 整理 86+ 篇文章 metadata（標題、描述、分類、關聯）。
2. 建立 Topic / User 雙層標籤，並指定標籤 owner。
3. 設計 30 組測試問題（涵蓋各身份、年級、目標、問題類型，作為驗收基準）。
4. 建立 FastGPT 知識庫（Embedding → 向量庫，並設好 MDX 更新同步流程）。
5. 建立 TBD API proxy（前端 → TBD API → FastGPT，禁止前端直連 OpenAI）。
6. 完成首頁與知識庫首頁的 AI 導航員入口 UI（顯眼、零摩擦、品牌一致）。
7. 設定 GA4 事件追蹤（入口曝光/點擊、AI 推薦文章 CTR、轉換錨點，並先取 baseline）。
8. 測試 Pagefind fallback（API 異常情境）。
9. 完成預算池與自動降級邏輯（達上限 → 切 Pagefind）。
10. 內測通過 MVP 上線驗收標準後上線。

## 最終結論

這份企劃的本質，不是「導入 FastGPT」，而是 **TBD 的 AI 第一印象策略**。

TBD 真正想買的，不是一個聊天框，而是「**AI × 教育顧問**」這個無人佔據的品牌定位。FastGPT 只是把 TBD 已有的優勢——86+ 篇結構化內容、真實案例、顧問能力——放大並包裝成第一印象的載體。

它把這些零件串成一個會自轉的飛輪：

```
內容 → AI 導航 → Growth Compass → 顧問 → 案例 → 內容
```

以 TBD 現階段（86+ 篇成形的內容體系、成長中的 IG、暑假持續擴張的知識庫、未來的 Growth Compass）來看，現在正是甜蜜點：**內容夠用、成本夠低、定位夠新、下檔夠淺。** 投資邏輯清楚——成本隨用量浮動、零使用近零成本、帳單保證有上限，最壞情況仍有第一印象保底，所以是保險而非賭注。唯一不可妥協的，是把第一印象做到夠好；只要守住這條，這筆投資就回本，而且有機會讓飛輪越轉越快。
