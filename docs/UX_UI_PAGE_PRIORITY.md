## 哪些頁面最需要優化?為什麼?

**前五名:services、resources、文章模板、首頁、cases。**

1. **services 是轉換漏斗的中樞卻是壞的**——所有「我適合什麼」的流量(首頁管道卡、狀況卡、子頁返回、plans/audience 舊連結)都匯到這頁,但它的核心互動(狀況卡→方案)點了落不到承諾的位置、比價所需的價格完全缺席。這是「使用者無法完成任務」等級,不是體驗瑕疵。
2. **resources 是流量最大的內容入口卻對回訪者不可用**——96 篇文章的檢索功能被三段導購內容壓到第 5.3 屏,手機 31 屏。SEO 與社群策略養出來的流量,在站內找不到路。
3. **文章模板一改動全站 96 頁**——麵包屑破版是社群讀者的第一印象;「文章→服務」斷鏈是全站最弱的轉換路徑。模板級修改的杠杆最大。
4. **首頁問題都是小修但面向付費決策者**——家長入口與價格透明度直接影響諮詢意願。
5. **cases 是信任引擎但 7 缸只點著 1 缸**——tabs 不 sticky+切換不捲動,絕大多數訪客只看完第一個案例;同句引言重複則直接傷「真實性」這個賣點。

## 應該先改什麼?

**順序:404+麵包屑+對比色(半天,止血)→ services 錨點+價格卡(半天,修轉換中樞)→ cases 捲動/sticky(半天)→ resources 搜尋前置(1 天)→ 首頁家長入口+價格錨點(半天)。** 這五步全部是 XS–S 成本,不動資訊架構,一個 Sprint 內能把 P0 清空、P1 清一半;之後才進入 Phase 2 的 resources 重排與 services 分流重做(見 `UX_UI_IMPLEMENTATION_PLAN.md`)。
