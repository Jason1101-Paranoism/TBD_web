# 設計備審與作品集 Checklist（設計傳播研究所）

> 研究所作品集和申請大學、找工作的作品集不一樣。**大學看潛力、業界看產出、研究所看的是「你怎麼想」**——教授要從作品裡看出你的問題意識、方法與判斷，而不是你會用哪些軟體。
>
> 這份把送件要交的東西拆成四塊：作品集本身、選件與排序、作品說明、以及作品集與研究計畫的接合。
>
> **匯入 Notion**：Import → Markdown 後可切換成資料庫。
> **用 Google Docs / Sheets**：表格可直接貼上。

## 第二段：選件——少而深

研究所作品集的常見失誤是「把所有做過的都放進去」。

| 作品 | 在解什麼問題 | 我在其中做了什麼決定 | 與我的研究方向的關係 | 收/不收 |
|---|---|---|---|---|
|  |  |  |  |  |
|  |  |  |  |  |
|  |  |  |  |  |
|  |  |  |  |  |
|  |  |  |  |  |

- [ ] 總件數控制在 **5–8 件**，寧可少不要雜。
- [ ] 每一件我都說得出「我在其中做了什麼決定」——不是「我負責視覺」。
- [ ] 沒有純粹展示軟體技巧、但沒有問題意識的作品。
- [ ] 團體作品有明確標示我的角色與貢獻範圍。
- [ ] 課堂作業可以收，但我補上了課堂要求以外我自己多做的部分。

## 第三段：排序

| 位置 | 放什麼 | 我的安排 |
|---|---|---|
| 第一件 | 最能代表我研究方向的那件（教授最可能只看前三件） |  |
| 第二、三件 | 展現方法多樣性或思考深度 |  |
| 中段 | 其餘作品，依主題或時間成組 |  |
| 最後一件 | 留一件收尾強的，不要用最弱的作品結束 |  |

- [ ] 第一件和我研究計畫的題目對得上。
- [ ] 整本翻完看得出一條線索，不是隨機拼盤。

## 第四段：每一件的作品說明

作品說明是研究所作品集和其他作品集差最多的地方。

| 欄位 | 寫什麼 | 這件的內容 |
|---|---|---|
| 標題與年份 | 基本資訊 |  |
| 一句話定位 | 這件在解什麼問題 |  |
| 脈絡 | 課程／自主／接案？限制條件是什麼 |  |
| 我的角色 | 團體作品必填，個人作品也要寫負責範圍 |  |
| 過程 | 最關鍵的一個決定，以及為什麼這樣決定 |  |
| 結果與反思 | 做完之後你知道了什麼；沒解決的是什麼 |  |

- [ ] 每件都有「反思」，而且不是自我稱讚。
- [ ] 說明文字用的是**判斷**的語言（我選擇、我排除、我發現），不是**流程**的語言（我先做A再做B）。
- [ ] 圖片解析度足夠、順序與文字對得上。

## 第五段：讓作品集支撐研究計畫

兩份文件要互相指涉，不是各寫各的。

| 檢查 | 我的情況 |
|---|---|
| 研究計畫裡提到的觀察或經驗，作品集裡找得到對應的那件 |  |
| 作品集裡至少有一件，是我研究問題的「前身」 |  |
| 研究計畫的方法，和我作品集展現的工作方式一致 |  |
| 如果教授只看作品集，他猜得到我想做什麼研究 |  |

- [ ] 這四格都能填，而且填的不是同一句話換句話說。

## 第六段：送件前最後檢核

- [ ] 檔名符合規定，且含我的姓名與報考系所。
- [ ] PDF 在別台電腦與手機各開過一次，字型沒有跑掉。
- [ ] 線上連結不需登入、不需密碼，且我用無痕視窗確認過。
- [ ] 所有引用的他人素材都有標示來源。
- [ ] 全文沒有錯字，尤其是教授姓名與系所全名。
- [ ] 我留了緩衝——不是截止日當天才上傳。
