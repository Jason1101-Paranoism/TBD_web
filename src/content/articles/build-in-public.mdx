<section class="article-section" id="what-is-bip">
## 什麼是 Build in Public

Build in Public 的核心概念很簡單：**不要等到東西做完了才分享，在做的過程中就把進展、想法、和遇到的問題公開出來**。

在工程師和創業者的世界裡，這個做法很常見：有人在 Twitter 上分享他做產品的每週進展；有人在 YouTube 上記錄他學習程式的過程；有人在 GitHub 上公開一個還在開發中的專案，讓別人能看見它是怎麼一步步長出來的。

對高中生來說，Build in Public 不一定要很正式，也不需要有很多觀眾。它可以是：

- [GitHub 上持續更新的 commit history](/pages/resources/github-commit-guide.html)
- Notion 頁面上記錄你每週在做什麼
- 偶爾在 Instagram 或 LinkedIn 分享你做的東西的截圖
- 在學校社群或 Discord 裡說「我最近在做 XX，遇到了 XX 問題」

只要你在做事的過程中留下了公開的痕跡，這就是一種 Build in Public。
</section>

<section class="article-section" id="why-it-works">
## 為什麼公開學習比私下學習有效

**它讓你對自己負責。** 當你知道你說了「這週要完成 XX」而且有人可能看見，你更不容易食言。這種外部的輕微壓力，比純粹的自律更容易維持。

**它讓你更認真整理自己的思考。** 為了讓別人看得懂你在做什麼，你需要把混亂的進度整理成清楚的說明。這個整理的過程，往往讓你對自己在做的事情有更深的理解。

**它吸引對的人出現。** 當你公開分享你在做什麼，和你有類似興趣的人更容易找到你——可能是有同樣問題的學生、可能是有建議的前輩、可能是想一起做事的隊友。這些連結，在私下學習的時候幾乎不會發生。

**它讓你的學習有持續的紀錄。** 六個月後，你能清楚看見自己從哪裡開始、走到了哪裡。這個紀錄，是備審和面試最真實的素材來源。
</section>

<section class="article-section" id="for-application">
## 對升學申請的實際意義

Build in Public 的最直接效果，是讓你的學習歷程從「事後重建」變成「即時記錄」。

大部分學生在高三整理備審的時候，都在靠回憶重建三年的故事。這個過程很痛苦，因為很多細節記不清楚了，而且沒有具體的紀錄可以佐證你說的話。

如果你在過程中一直有留下公開的痕跡——GitHub 的 commit、Notion 的進度更新、社群上分享的截圖——[整理備審](/pages/resources/personal-statement.html)的時候，你就有大量可以直接引用的素材，不需要靠回憶，故事也更有說服力因為它是有時間戳的真實紀錄。

另一個影響是在面試裡。當教授問「你在做這個 Side Project 的時候遇到了什麼困難」，如果你有當時記錄的問題和解法，你能說出非常具體的回答，而不只是「呃……好像有遇到一些問題，後來解決了」。
</section>

<section class="article-section" id="how-to-start">
## 高中生怎麼開始

**從最小的行動開始，不要設計一個複雜的系統。**

最容易開始的做法：每週或每隔幾週，花五分鐘寫幾句話——「這週我在做 XX，進度是 XX，遇到的問題是 XX」——放在任何一個地方（Notion、Instagram、GitHub 的 README）。

不需要每篇都很精彩，不需要每次都有重大進展。Build in Public 的力量來自於持續，而不是每次都很精緻。

**讓分享的成本極低。** 如果每次分享都需要花很多時間準備，你很快就會停下來。找一個對你來說最自然的形式——如果你本來就在刷 Instagram，就在限時動態裡放你的作品截圖；如果你習慣用 Notion，就在上面加一個「進度日誌」的頁面；如果你在用 GitHub，就讓 commit 訊息寫清楚，這本身就是 Build in Public。

**不要等到「有值得分享的東西」才開始。** 這個等待會無限延後。分享的過程中，「正在做但還沒完成的東西」和「遇到的問題」，其實比「做完的成果」更有真實感和連結感。
</section>

<section class="article-section" id="platforms">
## 在哪裡公開

選一個你本來就在用、分享成本最低的平台：

**GitHub**：如果你在做程式相關的 Side Project，持續 commit 並且寫清楚的 commit 訊息，就是最自然的 Build in Public。GitHub 的 contribution graph（那個綠色方格圖）是一個很直觀的長期投入視覺呈現。

**Notion（對外分享）**：把你的學習歷程頁面設定公開，附上你想讓人看見的進度和筆記。這個方式幾乎不需要額外準備，只要你本來就在用 Notion 整理東西。

**Instagram / Threads**：對設計、商管、傳播方向的學生，IG 是最自然的分享管道。作品截圖、設計過程、學習心得，都可以用視覺化的方式分享。

**LinkedIn**：如果你已經有 LinkedIn 頁面，定期更新你的 Side Project 進展或學習成果是很自然的使用方式，也讓相關領域的人更容易找到你。

不需要在每個平台都有存在感，選一個就夠。一致地在一個地方更新，比分散在四個平台但每個都很零散更有效。
</section>
