# 理工備審資料 Checklist

> 理工備審的核心：在團隊成果中切出你的個人貢獻，展現研究潛力與專業軌跡。
>
> **匯入 Notion**：Import → Markdown 後，勾選項會變成 to-do。

## CV

- [ ] 每段專題經歷都寫出：任務、方法、工具、成果、個人貢獻
- [ ] 團隊專題有明確寫出「我負責」的部分，不是「我們做了」
- [ ] 列出的技能與工具，都能在經歷中找到實際使用的證據
- [ ] 有具體數字或成果描述（效能、規模、名次），不是形容詞
- [ ] 一頁為原則，最重要的經歷放最前面

## 自傳

- [ ] 回答核心問題：我如何一步一步形成現在的研究興趣
- [ ] 沒有「從小喜歡科學」式的空泛開場
- [ ] 每個轉折都對應到可查證的節點（課程、專題、實習）
- [ ] 結尾接到未來的研究方向，與研究計畫書一致

## 專題成果

- [ ] 關鍵數據已整理成清楚的圖表，每張圖能一句話說出結論
- [ ] 有寫出遇到的技術瓶頸與除錯過程，不是順利的流水帳
- [ ] 程式作品有整理過的 GitHub 或報告（README 清楚、能看出你負責的部分）
- [ ] 不理想的數據有說明原因與修正方式

## 整體一致性

- [ ] 研究計畫書提到的每項核心工具，CV 裡有對應經歷
- [ ] CV 最強的技術經歷，研究計畫書有用上
- [ ] 備審中的每段描述，口試被追問細節時都答得出來
- [ ] 各校要求的格式與頁數已逐校確認（以簡章為準）

## 常見失分點自我對照

- [ ] CV 只列修課名稱，沒有寫真的動手做過什麼
- [ ] 專題寫成流程紀錄，看不出我負責哪一段、解決了什麼
- [ ] 工具與方法宣稱在 CV 裡找不到證據
- [ ] 成果沒有數據或圖表支撐，只有形容詞
- [ ] 團隊專題沒有標明個人貢獻
- [ ] 備審方向與研究計畫、目標實驗室三者對不起來

## 經歷與素材盤點

- [ ] 修過的課與真的動手用過的工具
- [ ] 做過的專題：題目、我負責哪一段、產出
- [ ] 實習或研究室經驗與具體任務
- [ ] 寫過的程式、跑過的模擬、量過的資料
- [ ] 可以放進 CV 的成果（報告、競賽、專利、論文）
- [ ] 可以當推薦人的老師（至少兩位）

## 每段經歷該寫出的五件事

- [ ] 做的是什麼（題目與我負責的段落）
- [ ] 用到什麼工具與方法（要能被追問）
- [ ] 遇到什麼問題
- [ ] 怎麼判斷與排除
- [ ] 產出是什麼（數據、圖表、程式、報告）

## 送出前檢核

- [ ] 每一項工具與方法都能在經歷裡找到依據
- [ ] 專題寫出了我負責哪一段、解決了什麼
- [ ] 成果有數據或圖表支撐
- [ ] 團隊專題標明了個人貢獻
- [ ] 備審方向與研究計畫、目標實驗室三者一致
