## 重驗方式

這份 checklist 的價值在於「可以再跑一次」，不然它就只是第二份會過期的報告。

**一行驗完大部分**：

```bash
node scripts/audit-templates.mjs        # §06 全部、§07d、附錄 A1／A2／B
npm run verify                          # 同上，且有缺漏就擋部署
```

稽核腳本涵蓋的是**結構性**項目。以下幾項腳本驗不到，要手動查：

| 項目 | 怎麼查 |
|---|---|
| §02 五項 | `grep` 對應關鍵詞（見上表「查證方式」欄），設計那份特別要確認 `到到` = 0 |
| §05 九項 | 兩篇 `.mdx` 的 `tocItems` 與 section id 是否都在 |
| §07a／§07b | 看 `scripts/template-manifest.json` 有沒有任何一筆是 `delivery: "external"` |
| 附錄 C/D | 只能對著報告逐條看，沒有機器可驗的痕跡 |

**規則本身也會出錯**：這支稽核腳本的規則改過兩次，兩次都是同一個病——
**寫成字面比對**，把「製作可行性」「判斷：適合主動聯繫」「第一類追問」判成缺漏。
規則要比對概念不是比對字串；不準的稽核器比沒有更糟，因為它會讓人去改沒問題的東西。
下次擴充規則時先用現有 45 份跑一遍，確認沒有假紅燈再接上閘門。
