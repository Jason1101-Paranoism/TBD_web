### md 與 csv 必須成對更新

YC 只優化了 `.csv`，但 repo 每份模板是 `.md` ＋ `.csv` 成對、兩種格式都提供下載。
只換 CSV 會讓同一份模板的兩個下載檔內容不同。本次採 **A+ 流程**：

1. **機械重建**（`csv2md.py`）：用 v2 CSV 重建 md 的表格與檢核區，保留舊 md 的 H1、
   開頭說明區塊與文末「搭配文章」連結。
2. **孤兒偵測**（`orphans.py`）：diff 新舊 md，列出「舊有、新沒有」的網址與說明段落。
   第一次跑出 **12 個網址、30 段說明**。
3. **回填**：21 段純增補（查法提示、資料查詢入口）自動塞回「查證管道」段末；
   9 條「A ≠ B」助記檢核項逐條人工對應，**替換**而非附加 v2 的精簡版，
   所以項目數不變、也不會出現兩條意思相同的。
4. 最終孤兒：**網址 0、段落 0**。

> 三支腳本在 scratchpad、未進版控——它們是一次性的搬遷工具。真正需要長期存在的是
> `audit-templates.mjs`。下次若還有 v3，重寫成本遠低於維護成本。

## 四、為什麼把規格寫成腳本

審閱報告是一次性的產物，規格只存在報告裡。Batch1／Batch2 審完之後優化版停在 Drive、
repo 仍是 v1，中間沒有任何東西會提醒這件事——這就是為什麼要有 `audit-templates.mjs`。

它同時實作審閱報告第 E 節那條規則：**每次有新學群上線，要回頭檢查已結批的類型有沒有漏網**。
設計傳播 2026-08-21 上線時漏了 1 份比較表（8/23 才補審）；農生環境 8/23 上線時，
若沒有這支腳本會一次漏 5 份。

目前刻意**不接進 `npm run verify`**：現況 41/45 份有缺漏，接上去等於讓閘門永遠是紅的。
等 v2 落地、B3 三類補齊之後，再把 `--strict` 接進 verify 當回歸閘門。
