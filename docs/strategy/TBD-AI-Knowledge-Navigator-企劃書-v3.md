## Executive Summary

TBD 官網已累積 86+ 篇主題化知識文章，內容深度具備市場優勢。但在台灣升學顧問市場中，多數同業官網仍是靜態頁面，缺乏明顯差異化。

本專案導入 FastGPT，**不是為了取代搜尋、也不是打造 AI 顧問，而是用一個「會帶路的 AI 導航員」作為品牌的吸睛入口**——讓第一次接觸 TBD 的高中生與家長，立刻感受到「這是一個懂 AI、也懂教育的品牌」，並被自然地引導進知識庫、進而走向真人顧問服務。

關鍵判斷：**即使工具使用效果為零，吸睛效果本身已回本。** 而由於成本隨用量浮動、低使用即低成本，這個投資的下檔風險極小，唯一不可妥協的是「第一印象的品質」。

## 一、定位轉向：為什麼是「吸睛」而非「工具」

過去把 AI 當工具來規劃時，會掉進兩個陷阱：

第一，**追求使用率，就得把功能做複雜**（會員、額度、個人化），結果是把一個行銷誘餌，做成了一個沒人會深用的半成品。

第二，**用「使用率」當成敗標準，會錯估價值**。對一個內容已經夠好的品牌，AI 的邊際價值不在於「幫人找文章的效率」（86 篇用好的標籤與搜尋就能解），而在於**它本身就是一個會被看見、被討論、被截圖分享的品牌訊號**。

所以 v3.0 的前提是：

> AI 導航員首先是 TBD 的「門面」與「差異化標記」，其次才是知識庫的導覽工具。
> 我們設計它，是為了讓人「眼睛一亮並走進來」，不是為了讓人「天天回來用」。

這個轉向同時解決了 v2.0 的內部矛盾——原企劃用工具使用率的 KPI，卻又說目標是品牌定位；用會員額度的門檻，卻又想吸引流量。v3.0 讓邏輯一致。

## 二、專案目標與非目標

### 核心目標

1. **建立品牌差異化的第一印象**——讓 TBD 官網在同業中「看起來就不一樣」。
2. **降低首次訪客的探索摩擦**——用 AI 把人從「我不知道該看什麼」帶到「這篇就是我要的」。
3. **強化漏斗頂端的轉換**——把被吸引進來的人，順勢導向知識庫與顧問服務。

### 非目標（明確不做）

- 不做 AI 顧問：不分析錄取機率、不做個人化升學規劃、不診斷個別備審。這些保留給真人顧問。
- 不追求高使用率與深互動：使用率高是加分，不是成敗標準。
- 不在 MVP 階段做會員、登入、個人化紀錄。

### AI 角色定位

> AI 只負責「幫你找到答案在哪裡、該照什麼順序讀」，不負責「幫你做決定」。

---

## 三、產品定位

**一句話：** TBD AI 導航員——幫你找到下一步該看什麼。

**品牌定位：** Google Maps for Education（教育版導航，不是教育版顧問）。

**AI 身分：TBD AI 成長導航員**
任務：理解問題 → 推薦內容 → 規劃閱讀順序 → 引導至適當服務。

**語氣守則（沿用 TBD 教育語氣）：** 專業但親切、有溫度與陪伴感，避免「一鍵解決」「極致體驗」等誇大詞。核心原則：「共創，不代筆；引導，不操控；如實呈現，不憑空捏造。」

---

## 四、使用者體驗：第一印象就是一切

吸睛型功能的成敗集中在前 30 秒。設計優先序如下：

1. **入口要顯眼。** AI 導航員放在首頁 hero 區與知識庫首頁的最上方，並作為 IG Bio / LINE 選單的落點之一。它是門面，不能埋在深處。
2. **零摩擦。** 不登入、不擋次數即可試用。引導誘餌不該對使用者設關卡。
3. **永遠能用、永遠漂亮。** 寧可功能少，也要每一次互動都流暢、回答有條理、視覺乾淨。
4. **永遠導向內容與 CTA。** AI 不把答案講完，只給「問題理解 + 為什麼看 + 推薦順序」，把實質內容留在文章裡，避免零點擊。

### 使用情境

**Case 1**
使用者：我是高二自然組，想申請資工系。
AI：推薦閱讀 ①學習歷程主線是什麼 ②Side Project 如何選擇 ③資工系教授在看什麼。預估閱讀時間 25 分鐘。

**Case 2**
使用者：活動很多但很雜怎麼辦？
AI：推薦閱讀 ①活動不是越多越好 ②如何建立主線 ③教授如何看經歷。預估閱讀時間 15 分鐘。

**Case 3**
使用者：我想推甄研究所。
AI：推薦閱讀 ①推甄全攻略 ②推薦信規劃 ③研究計畫書撰寫。預估閱讀時間 30 分鐘。

每則回答固定結尾帶一個明確但不強迫的 CTA（例：「想讓顧問幫你看主線方向？預約策略諮詢」）。

## 五、產品架構與漏斗

### 漏斗（簡化、零摩擦）

```
IG / LINE
   ↓
官網（AI 導航員作為吸睛入口）
   ↓
知識庫文章
   ↓
顧問服務
```

Growth Compass 與會員個人化**不在主漏斗的必經路徑上**，列為未來選配（見 Roadmap Phase 後段）。

### AI 導覽流程

```
使用者問題 → FastGPT → 搜尋知識庫(RAG) → 整理答案 → 推薦文章與順序 → CTA
```

### 回答格式統一（AI 不自由發揮）

固定五段輸出：問題理解 / 核心建議 / 推薦文章 / 推薦閱讀順序 / 下一步建議。
固定格式同時達成三件事：成本可控、品質穩定、語氣一致。

## 六、知識庫標籤系統（保留）

即使是吸睛導向，AI 推薦的品質仍取決於底層標籤。這部分保留，因為它直接決定「第一印象好不好」。

**Topic Layer（沿用現有分類）：** 申請策略、備審製作、材料累積、面試準備、科系指南、研究所推甄、家長專區、工具資源。

**User Layer（新增）：**
- 身份：高中生 / 大學生 / 研究所申請者 / 家長
- 年級：高一～高三、大一～大四
- 目標：醫學 / 電資 / 工程 / 商管 / 設計 / 教育 / 研究所
- 問題類型：不知道做什麼 / 不知道選什麼 / 不知道怎麼寫 / 不知道怎麼準備

標籤治理需指定長期 owner，因為文章會持續增加。

## 七、技術架構（精簡版）

### 系統架構

```
Astro（靜態前台）
 ├─ MDX 知識庫
 ├─ FastGPT（RAG 問答）
 └─ Vercel（部署）
```

MVP 階段**不引入 Supabase**（會員 / 紀錄）；待未來確定要做個人化時再加。這讓 MVP 維持在「靜態站 + 一個 RAG API」的最小複雜度。

### 資料流程

```
文章 → Embedding → 向量資料庫 → FastGPT → 回答
```

需建立「MDX 更新 → 重新 Embedding」的同步流程（可手動或排程），避免推薦內容過時。

### 安全架構（不可省略）

```
前端 → TBD API → FastGPT
```

禁止前端直連 OpenAI，避免 Key 洩漏與 Token 濫用。這層即使在 MVP 也要做。

## 八、成本與「保險型支出」論述

這版重新定義成本邏輯：

**500 元/月是「上限」，不是「固定支出」。** 它是預算池的天花板，實際成本隨用量浮動。
**若工具使用效果為零，成本不是 500，而是趨近於零**（只剩固定託管，沒有 token 消耗）。
換句話說，下檔風險極淺：用得多，代表它真的有用、花得值；用得少，幾乎不花錢，但吸睛價值已經兌現。

> 真正的投入是前期建置與維護工時，不是這每月 500 元。
> 月費這層便宜到可以當「保險 / 邊當」來買——最壞情況仍有吸睛保底，所以不算賭注。

### 成本治理（保留有效的、移除反吸睛的）

保留：

- **模型控制：** 優先低成本模型 + RAG，而非高成本深推理。
- **輸入限制：** 500 字內，避免整份備審 / 長作文 / PDF 貼文造成失控。
- **輸出限制：** 600 字內，目標是導航不是分析。
- **召回限制：** 每次 Top 4 文章即可，避免 Token 浪費。
- **月預算保護：** 達上限自動停用 AI，降級為靜態全文搜尋（Pagefind）。
- **安全架構：** 前端 → TBD API → FastGPT。

移除（因為與吸睛目標相衝）：

- ~~訪客每日 5 次額度~~ → 不擋，零摩擦。
- ~~登入會員才放寬~~ → MVP 不做登入。
- 唯一保留的硬上限是「月預算池」這個成本煞車，靠它而非個人額度來控成本。

## 九、唯一不可妥協：第一印象品質下限

吸睛的反面是「看起來像隨便接的陽春 chatbot」。那不只沒吸到睛，還會讓家長覺得 TBD 在跟風炫技，反而扣分——而 TBD 的信任感本來就該來自內容真實，不來自設計炫技。

因此本專案設一條紅線：**寧可砍功能，也要守住品質。**

上線前必須通過的檢核：

- 回答永遠流暢、不頓、不亂答；答不出來時誠實說明並導向人工或搜尋。
- 每則回答都導得到至少一篇真實存在的文章，且連結正確。
- 視覺與語氣符合 TBD 品牌（乾淨、有溫度、不誇大）。
- 桌面（1280px）與手機（375px）皆完整可用。
- 任何情況都有 fallback（預算用罄 / API 異常 → Pagefind 搜尋）。

## 十、KPI（吸睛導向）

先決條件：**所有指標上線前都要用現有 GA4 取得 baseline**，否則無法判斷成效。

### 第一印象 / 吸引（主指標）

- AI 導航員入口的曝光與點擊率（首頁 hero、知識庫首頁）。
- 首次互動後的留站行為（是否點進推薦文章）。
- 自然口碑訊號（社群提及、截圖分享——質化追蹤即可）。

### 內容銜接（次指標）

- AI → 文章點擊率（被吸引後是否真的走進內容）。

### 單一轉換錨點（證明價值的關鍵）

- **用過 AI 導航 vs 沒用過的訪客，顧問預約率差異。**
  這一條若成立，整個投資就站得住——它把「吸睛」翻譯成商業價值。

刻意不追：AI 使用率門檻、平均互動輪數。這些是工具導向的指標，與本專案目標不符。

## 十一、Roadmap

### Phase 0（約 1 週）— 知識庫整備

統一 metadata、建立 Topic/User 雙層標籤、建立文章關聯、指定標籤 owner。

### Phase 1（約 1～2 週）— AI 導航員 MVP（本專案重心）

純前台 RAG 問答：問答、推薦文章、引用來源、固定格式輸出、CTA、Pagefind fallback。
放上首頁與知識庫首頁的顯眼入口。**全部資源集中在把第一印象做到無懈可擊。**

### Phase 2（未來選配，非承諾）— 會員與紀錄

若 Phase 1 數據顯示值得，再導入 Supabase 與使用紀錄。需先備妥未成年資料的同意與隱私政策。

### Phase 3（未來選配，非承諾）— Growth Compass 整合

個人化推薦、學習路徑、案例匹配。屬長期願景，不在本次投資承諾範圍。

> 與 v2.0 的差異：Phase 2/3 從「排程內的承諾」降級為「數據驗證後才啟動的選配」，避免一開始就把架構做重。

## 十二、風險與緩解

- **第一印象做不好反而扣分** → 設品質下限紅線（第九節），不達標不上線。
- **零點擊稀釋閱讀** → AI 只導讀不答完，實質內容留在文章。
- **標籤維護長期負擔** → 指定 owner，納入新增文章的流程。
- **未成年資料隱私** → MVP 不收個資；Phase 2 前先備齊同意與保存政策。
- **新鮮感衰退** → 吸睛靠的是「導向真正的好內容」，而非 AI 本身，可持續性由 86+ 篇內容深度支撐。
- **架構複雜度上升** → MVP 維持「靜態站 + 一個 RAG API」最小集合，後台延後。

---

## 十三、預期效益

**對使用者：** 更快找到答案、更低探索摩擦、第一次接觸就有好印象。

**對 TBD：**
- 在同業中建立明顯的品牌差異化（AI × 教育顧問）。
- 提升內容利用率與 SEO 內容價值。
- 強化漏斗頂端，順勢提升顧問服務轉換。
- 以極低的下檔風險（零使用 ≈ 零成本）換取吸睛與品牌定位的上檔空間。

---

## 最終結論

TBD 導入 FastGPT 的本質，不是打造 AI 顧問，也不是賭一個高使用率的工具，而是**用一個會帶路的 AI 導航員，作為品牌的吸睛入口與差異化標記**。

它把 TBD 既有的知識庫與未來的顧問服務串成一條順暢的漏斗：

```
知識庫 → AI 導航員 → 顧問服務
```

在已擁有 86+ 篇主題化內容的基礎上，這個投資的邏輯很清楚：**成本隨用量浮動、零使用趨近零成本，最壞情況仍有吸睛保底，所以它是保險而非賭注。** 唯一不可妥協的，是把第一印象做到夠好——只要守住這條，這筆投資就回本。
